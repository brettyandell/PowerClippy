Power Platform admin reference

Governing how agents are shared

Who can share an agent, who can find it, who can run it, and whose identity it acts as are decided in three different admin centers. This page maps every control Microsoft documents today and shows how they stack.

Basis: Microsoft Learn, current as of late October 2026 Covers: Copilot Studio, Agent Builder, Agent 365, Entra Agent ID Audience: Power Platform, AI, and Global administrators
01

Three control planes

Each admin center answers a different question. No single one can lock an agent down on its own.

02

Two separate sharing systems

Microsoft states that the Microsoft 365 sharing control "only applies to agents built with Microsoft Copilot Agent Builder", and that it is different from the Power Platform sharing limit. Setting one does nothing to the other.

03

The access gates a chat request passes

A user reaches a Copilot Studio agent only if every gate allows it. Environment access and sharing are separate controls: sharing an agent doesn't get anyone past the environment's security group, and group membership doesn't grant access to any particular agent.

04

07

Entra Agent ID: the agent's own identity

When a maker publishes a Copilot Studio agent, the platform gives it an Entra Agent ID and attaches API permissions for each connector it uses. You can review those permissions in Entra and target them with Conditional Access. Entra Agent ID is in preview.

08

New rules don't remove existing access

This applies to both the Power Platform sharing limits and the Microsoft 365 Agent Builder sharing setting. It's the most common reason an audit still finds tenant-wide agents after rules are in place.

09

Gotchas the docs call out

  • Unauthenticated agents bypass sharing

    With No authentication, anyone with the link can chat, and sharing limits don't apply. Block the "Chat without Microsoft Entra ID authentication" connector in a data policy.

    Power Platform
  • "Everyone" includes guests

    The Everyone group contains every account that has ever signed in, guests included, and its membership can't be viewed or edited. Share with a security group instead.

    Power Platform
  • The default environment can't have a security group

    Gate 4 doesn't exist there. Use sharing limits, data policies and environment routing to move makers out.

    Power Platform
  • Sharing quietly grants maker rights

    A System Administrator sharing an agent assigns Environment Maker to people who lack the ChatBotReaders privilege, which also lets them build agents.

    Power Platform
  • Owners can't be removed by other sharers

    Owners always keep access. To cut off an owner, reassign ownership or block the agent.

    Microsoft 365
  • IP firewall can block M365 admin actions

    In active enforcement mode, block or reassign from the M365 admin center fails. Run it through the Power Platform API instead.

    Microsoft 365
  • Blocking scope depends on the builder

    Blocking a Copilot Studio or Agent Builder agent affects Copilot, Teams and Outlook. Blocking a SharePoint or Foundry agent affects Copilot Chat only.

    Microsoft 365
  • Agent users skip "all users" policies

    Conditional Access policies that target all users don't include agent user accounts, and group-based targeting isn't supported for them.

    Entra

11

Runbook

Do these in order. Cleanup comes before rules because rules don't remove existing access.

  1. Inventory. Open Power Platform admin center › Manage › Inventory, filtered to agents. Export it. Flag agents shared with Everyone, agents with no authentication, and agents whose tools use maker connections.
  2. Contain. Unshare overshared agents, or quarantine them with pac copilot-studio set-bot-as-quarantined while you talk to the owner.
  3. Force sign-in tenant-wide. In a tenant data policy, block Chat without Microsoft Entra ID authentication in Copilot Studio and Direct Line channels in Copilot Studio where they aren't needed.
  4. Make environments managed and add sharing rules. Default and personal environments: Editor and Viewer sharing off. Team environments: individuals only, with a viewer cap. Apply them through environment-group rules.
  5. Gate distribution in Microsoft 365. Set Agents › Settings › Sharing to specific users, set User access to licensed groups, and approve every Copilot Studio publish request with a scoped audience.
  6. Automate lifecycle. Add management rules: block ownerless agents with no usage, and reject publish requests older than 30 days.
  7. Identity layer (if you have E7 or Agent 365). Assign sponsors, apply the block-high-risk-agent Conditional Access template, and review the Entra permissions attached to each agent.
  8. Review monthly. Check the inventory, the Requests list, the ownerless-agents card and the Security Dashboard for AI.
